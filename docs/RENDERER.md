# Comic renderer and assets

## How a page is built

```
backend scene_view().page  ──►  sanitizePage()  ──►  <ComicPage>  ──►  <ComicPanel> × n
(closed vocabulary ids)         (drops unknown ids,                      SceneBackground  (environment art)
                                 trims text, caps panels)                EffectOverlay    (trusted SVG components)
                                                                         CharacterLayer   (portrait art)
                                                                         PanelFrame       (SVG border, halftone, burst)
                                                                         NarrationBox / SpeechBubble (plain text)
```

- **Layouts:** `single`, `two`, `three`, `revelation`, `dialogue` (panel caps 1/2/3/1/3).
- **Bubble kinds:** `speech`, `thought`, `shout`, `radio`.
- **Nothing arbitrary reaches the DOM.** Scene data can only name ids from the closed lists in
  `src/comic/types.ts`; text is rendered as React text nodes (tests assert markup in dialogue is shown
  literally; another test fails the build if `dangerouslySetInnerHTML`/`innerHTML`/`eval` appear in `src`).
- **Missing art never breaks a scene:** if a drawing cannot render, the original placeholder image is shown
  instead (`ArtBoundary`); if that image is missing too, an environment becomes a labelled gradient and a
  character a silhouette with initials.
- **Accessibility:** each panel is a `figure` with a generated description; bubbles are labelled groups
  ("Kavya Rao says"); decisions are a keyboard radio group (Tab / Enter / number keys); HUD values are
  `role="meter"`; animation stops under `prefers-reduced-motion`.

## The hand-inked art (`src/comic/art/`)

The comic is drawn in the browser from parameters, in a mature ink style (heavy contour, varied line weight,
hatched shadows on the side away from the light, restrained navy / charcoal / steel with amber for emergency
light and red only for danger). It reads only what the backend already sends for a panel (environment,
characters with their stored expression and side, effects, narration, dialogue with its bubble kind, emphasis)
and never changes it.

| File | Job |
|---|---|
| `emotion.ts` | Turns the stored expression plus the situation (effects, bubble kind, wording of the panel, who is speaking) into one of 12 emotions: composure, fear, suppressed panic, suspicion, frustration, exhaustion, determination, regret, alarm, anger, concern, urgency. Each is a set of numbers (brow lift/angle/asymmetry, lid weight, squint, mouth, jaw clench, bags, sweat, head drop, shoulders, gaze). A small per-panel jitter stops repeats looking stamped. |
| `looks.ts` | One fixed identity per character (face shape, hair, glasses, stubble, outfit, colours). Never mixed between panels. |
| `Figure.tsx`, `poses.tsx` | Draws a character from a look, an emotion and a pose (hand on keyboard, pointing at a map, palm out to hold people back, holding a report or tablet, radio, hand to chin or neck, pen hovering over a report...). Also front, three-quarter and from-behind views and head-and-shoulders portraits. |
| `environments.tsx`, `geometry.tsx` | Nine inked environments built from perspective planes, props and light sources; lights and screens go dead on `power_failure` and screens show a red alert on `system_alert`. |
| `shots.ts` | Plans each panel: wide, detail, medium, close-up, over-the-shoulder, group, reveal or quiet. Chooses camera crop, depth of field, who stands where, what they are doing, where they look, and the page's panel shapes and columns. Deterministic. |
| `Scene.tsx`, `Evidence.tsx`, `ArtBoundary.tsx` | Environment through the camera window; the wordless evidence insert; the fallback boundary. |

If the scene data does not say something (for example a pose), a fixed presentation default from `shots.ts` is
used. Nothing here is sent to the backend. The gallery (`#/gallery`) has reference sheets showing every
character in every emotion, every pose and every costume.

## Interface components

`DecisionList`/`DecisionCard`, `SimulationHUD`, `StakeholderCard`, `EventPanel`, `DeadEndScreen`,
`RecoveryTimeline`, `OutcomeReport` (in `src/ui`). They only display data from the API; none compute outcomes.

## Assets

`frontend/public/assets/manifest.json` maps ids to files (environments, character poses, effects, ui).
The files in `public/assets` are the **original placeholder set** generated by `npm run assets`
(`tools/generate-assets.mjs`): 9 environments (1600×900), 6 characters × 8 expressions (600×800, transparent),
3 UI files. The comic no longer shows them while the drawn art works: they are the fallback when a drawing
fails to render, and the manifest still lists them. Effects are code (`kind: "component"`), not files.

To use final artwork instead: drop a file with the same name and size over the placeholder (SVG, PNG or WebP;
update the `path` in the manifest if the extension changes). Do not rerun `npm run assets` afterwards: it
regenerates the placeholders. Tests check that every manifest path exists and that every id the renderer
accepts has an entry; a backend test checks every id used by the page scripts is in the manifest.

## Regenerating fixtures

`backend/tools/dump_fixtures.py` captures real API responses into `frontend/src/fixtures/views.json`
(used by the gallery and UI tests). Re-run it after changing scenario content.

## Gallery

`npm run dev`, then open `http://localhost:5173/` to see every layout, bubble kind, effect, expression,
the dead-end screens and outcome reports using real backend data.
